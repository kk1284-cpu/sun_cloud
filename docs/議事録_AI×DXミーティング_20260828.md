## 3. 引き継ぎ文書との差分（ここが重要）

`引き継ぎ_MCQ113_ノウハウと履歴_20260828.md` は同日付だが、この会議より前の整理。
以下は会議で置き直された点。

### 3-1. 運用開始日が 9月1日に確定した

引き継ぎ文書ではトライアル期間を 8/1〜11/30 とだけ置いていた。
会議で **9/1（火）から会議参加メンバー・トライアルメンバーで開始**と確認された。

⚠ 一方で青木さんは「**10月開始**に向けて入力環境を整える」と述べている。
**9/1 と 10月の2つの日付が出ている。** どの範囲が9/1で、どこから10月なのかは要確認。

### 3-2. Slack が「後回し」から「調査タスク」へ上がった

引き継ぎ文書 3章（8/18のAIミーティング）では入力経路を
「フォーム／Google Chat／Slack の3種。**Slackは後回し**」としていた。

会議では、**サンガーデンキラが Slack をフル活用**しており、
3ヶ月で消えてもよいデータでやりくりしている現状が長峯さんから報告された。
長峯さんは「いまのSlackを活かした形を継続できる方法を検討してほしい」と要望している。

松山さんの調査報告：
- **Slack の MCP 単体では保存ができない**
- **Google ドライブと MCP を組み合わせる方法**で対応できそうな見込み

運用の落とし所として、**Slack → Googleスプレッドシートへ転記して恒久保存**が決定事項3になった。
加藤さんの説明「スプレッドシートにデータが残るため永久に保存される」で長峯さんは納得している。

→ **入力4経路の設計（引き継ぎ文書4章）に Slack を正式に足す必要がある。**

### 3-3. フォームの質問数削減が正式タスクになった

石川さん・神田さんから「**Googleフォームの質問数が多いと現場の負担が増え、残業増加につながる**」
という懸念が出た。

松山さん・加藤さんの回答が設計上の要点：
> **日報の質問数が少なくても、GCシートに必要な要素が盛り込まれていれば
> AIが適切に抽出してシートを作成できる。**

→ 引き継ぎ文書 5-6「機械が書かない欄は意図して空ける」と同じ思想。
入力側も同様に、**問いを減らしてAIの抽出に寄せる**方向で確定した。

### 3-4. チャレンジシート → マンダラチャートへの置き換えが動き出した

引き継ぎ文書 10章では「CS面談シート（3ヶ月シート）の扱いが宙ぶらりん」としていた。

会議で、**加藤さん・松山さんの共同タスクとして「チャレンジシートをマンダラチャートへ
置き換えるための運用手順の策定」**が立った。松山さんは石川さんの質問に対し、
日報を続けることで週次のGCだけでなく**四半期・半年のマンダラチャート
（チャレンジシートに相当する目標進捗管理シート）も自動で構築される仕組み**を
年末に向けて開発中と説明している。

→ 宙ぶらりんが一つ解けた。**チャレンジシートは廃止ではなく、マンダラチャートへ置き換える。**

### 3-5. EXP を人事評価に使わない線は、顧客側にも共有済み

レクチャの中で「**この経験値データは人事評価には使用せず、ゲーミフィケーションとして
楽しむもの**」と明示的に説明されている。引き継ぎ文書 5-5 の線は会議の場で共有された。

### 3-6. 実データでの手応え

大串さんが実際に2日分の日報を読み込ませたところ、
**AIが生成した成果等の内容が自身の記述とほぼ一致していた**と報告。
