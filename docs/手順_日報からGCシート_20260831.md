# 4. 自動で動くもの

| いつ | 何が起きるか | どこに出るか |
|---|---|---|
| 30分ごと | 4経路から日報を集め、見出し付きの1本文にそろえる | 「日報統合」シート |
| 1時間ごと | 未判定を15件ずつ、AIが96項目のどれかに判定 | 「分類済み」→「活動記録」 |
| 金 16:00 | 週次の応援メール | ご本人のメール |
| **金 17:00** | **GC下書きをシートに書き出す** | **「GC下書き」シート** |
| **金 17:30** | **下書きをスライドにして個人フォルダへ** | **納品フォルダ／人ごと** |
| 毎月1日 7:00 | 月次の日報解析レポート | メール |

## 35名でも間に合うか

**間に合います。** 35名が毎日書くと1日35件、1時間ごとに15件ずつ処理するので、
**1日あたり2〜3時間で追いつきます。** 夜のうちに片づく計算です。

⚠ ただし**いまはAIの無料枠で動いています。** 追いつかない日が出たら、
メニュー **②** を押せばその場で進みます。有料への切り替えも検討中です。

# 6. 13欄のうち、7欄が埋まります

## 自動で埋まる 7欄

- 今週の中心課題・取り組むテーマ
- 何をどのように実践したか
- 鍵となる発見・気づき／予期せぬ成功・失敗
- すぐに取り組むべきこと
- 用いたフィロソフィ
- 今週の Key Takeaway
- 外に生み出した成果（6分類に振り分け）

## 意図して空ける 6欄

- 外的な変化 ／ 内的な変化
- 効果的な計画
- 実践に用いたドラッカーのコンセプト
- 私のフィロソフィ目標
- フィードバックコメント

⭐ **空けているのは、AIが書けないからではなく、書かないと決めたからです。**
内面のことばは、ご本人が書く欄として残しています。
書く時間を省いたぶんを、対話に使っていただく設計です。

# 7. 手で今すぐ作りたいとき

スプレッドシートの上部メニュー **🌞 SUN日報解析** から操作します。

| やりたいこと | 押すもの |
|---|---|
| 溜まっている日報を今すぐ判定する | **② 未分類の日報をまとめて分類** |
| 判定が違っていたので直したあと反映する | **③ 分類済み→活動記録 再取り込み** |
| いまどこまで進んでいるか見る | **⑩ 分類の進捗を見る** |
| 週の下書きを今すぐ作る | エディタで `tkGCスライド_今週分を作る` |
| 先週ぶんを作り直す | エディタで `tkGCスライド_先週分を作る` |

**エディタ**＝スプレッドシートの 拡張機能 → Apps Script

⚠ **判定が違っていたとき**は「分類済み」シートの判定コードを直して ③ を押します。
基準そのものを変えたいときは「クエスト表」シートの列を書き換えます。**コードの修正は要りません。**

# 8. 8/31（月）に終わらせること

**この3つが済んでいないと、9/4に35名分の下書きは出ません。**

🔴 **順番があります。** 名簿 → 取り込み → テンプレ → トリガー。
名簿より先に取り込むと氏名が壊れ、あとから直せません（8-1参照）。

## 8-1. 名簿35名の登録（10分）★いちばん先にやる

`トライアルメンバー35名_貼付用_20260831.tsv` を「メンバー」シートに貼ります。
メールアドレスは整形済み、部署も対応づけ済みです。

⭐ **いま「メンバー」シートは空**で、応援メールが5週続けて「対象0名」になっています。
これを入れると解消します。

### 🔴 名簿より先に取り込むと、氏名が壊れます

日報フォームの名前欄は、**氏名とフィロソフィがひと続き**で入っています。

```
大山恵子 感謝の心で
下岡 礼奈 信頼関係を築く
煙草 健一  楽観的に構想し 悲観的に計画し 楽観的に行動する
```

システムは**名簿と突き合わせて氏名だけを取り出します。**
名簿があれば `大山恵子`、無ければ `大山恵子 感謝の心で` のまま入ります。

実データ7名で試したところ、**名簿が空だと6名が誤った氏名で保存されました。**

⚠ **一度取り込んだ行は、二度目は飛ばされます。** あとから名簿を入れても直りません。
氏名が違うと、その人の日報が別人扱いになり、**下書きに1件も入りません。**

**必ず、名簿を貼ってから取り込みを回してください。**

## 8-2. スライドのテンプレ準備（★手作業・1回だけ・1〜2時間）

下書きは**テンプレートの `{{NAME}}` `{{THEME}}` などを差し替える方式**です。
その**13個の目印を、スライドの回答欄に人が貼る作業**が1回だけ要ります。
回答欄は空のテキストボックスなので、コードでは狙えません。

```
顧客原本 ── 読むだけ。書き込まない
   ↓ tkGCスライド_下書きテンプレを用意() でコピー
下書き用テンプレ ── ここに13個の目印を貼る　★ここが手作業
   ↓ config の TEMPLATE_ID に設定
   ↓ tkGCスライド_個人フォルダ準備() で35名分のフォルダを作る
毎週 金17:30 ── 個人フォルダに自動で届く
```

手順は `設置手順_AppsScript_20260831.md` の**第3部**にあります。

## 8-3. トリガーを入れる（数分）

エディタで次の2つを1回ずつ実行します。

| 関数 | 入るトリガー |
|---|---|
| `tkGC下書き_トリガー設定` | 金 17:00　シートへ書き出し |
| `tkGCスライド_トリガー設定` | 金 17:30　スライドにして個人フォルダへ |

# 9. いま正直にお伝えしておくこと

## 9-1. 拾えるのは、いまは薬局のフォームだけです

ネットワークと花のある家は**フォームが止まり、Google Chat に移っています。**
ボードメンバーの日報も Chat です。

**Chat からの取り込みは9月に実装します。** それまでは、
**ネットワーク事業課6名のぶんが下書きに入りません。**

⚠ **35名全員ぶんを今週作るなら、この6名には薬局フォームに書いていただく**か、
Chat取り込みを待つかの二択になります。**ご相談させてください。**

## 9-2. 出てくるのは「下書き」です

確定版ではありません。**AIが下書きし、ご本人が確認して直す**形にしています。
グループコーチングが内省と対話の場である以上、そうすべきだと考えています。
それでも「毎回一から思い出して書く」時間はほぼ無くなります。

## 9-3. 初回は日報が少ないぶん、薄くなります

火曜スタートなので、初回は4日ぶんです。
**書いた量がそのまま下書きの厚みになります。** 2週目以降は厚くなります。

# 10. 困ったとき

| 症状 | 見るところ |
|---|---|
| 日報を出したのに判定されていない | 1時間ごとにまとめて動きます。急ぐときは **②** |
| 金曜に下書きが出ていない | **⑩** で残り件数を確認 → **②** で追いつかせてから作り直す |
| 判定が違っている | 「分類済み」の判定コードを直して **③** |
| 人の名前が取り違えられている | 「メンバー」シートの氏名を確認 |
| 成果の分類を変えたい | 「クエスト表」シートの列を書き換える。コード修正は不要 |
| 特定の人の下書きが出ない | その人の日報が0件か、「メンバー」に登録されていない |
