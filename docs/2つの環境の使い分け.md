# ローカルとクラウド、2つのClaude Codeの使い分け

この案件は2つの環境から進める。**リポジトリが唯一の正**で、両方がそこを読み書きする。
セッション同士は会話しない。同じ `CLAUDE.md` と `docs/` を読むことで足並みが揃う。

---

## 役割

| | ローカル（松山さんのPC） | クラウド（claude.ai/code） |
|---|---|---|
| **役割** | **手を動かす** | **考える・書く** |
| clasp push / pull | ⭕ | ❌ Googleにログインできない |
| PC上のファイル操作 | ⭕ | ❌ |
| Google ドライブ パソコン版の同期フォルダ | ⭕ 直接読める | ❌ |
| 動作確認・エラーを見て直す | ⭕ | ❌ |
| Google ドライブ／Gmail／カレンダーの参照 | 接続すれば可 | ⭕ |
| 移動中・スマホから | ❌ PCが要る | ⭕ |
| リポジトリの読み書き | ⭕ | ⭕ |

## 分担の原則

**PCかGoogleの認証に触るものはローカル。それ以外はどちらでもよい。**

| ローカルでやる | クラウドでやる |
|---|---|
| `clasp push` / `clasp pull` | 設計・権限の検討 |
| `.gs` のリポジトリへの取り込み | 議事録の読み込みと整理 |
| `config.gs` の編集 | 顧客向け文書の下書き |
| Apps Script の設置・トリガー | 手順書・設計図の更新 |
| 実物での動作確認 | 移動中の指示出し |

⭐ **`.gs` のリポジトリ移送はローカルの仕事。**
クラウドから移すと、ファイルの中身がモデルの出力を経由するため1バイト落ちることがある。
実際に `コード.gs` で日本語コメントが化けた（「APIキーの診断」→「APIキーの訽??」）。
ローカルなら同期フォルダのファイルをそのまま `git add` するだけで、化けようがない。

## 決まりごと

**作業を始める前に `git pull`、終わったら `git push`。** これだけ。

```
git pull origin claude/loading-request-lg3rym
（作業）
git push -u origin claude/loading-request-lg3rym
```

⚠ 両方で同時に同じファイルを触らない。
クラウドで文書を書いている間に、ローカルで同じ文書を直すとぶつかる。

## ローカルの始め方

```powershell
cd $HOME
git clone https://github.com/kk1284-cpu/sun_cloud.git
cd sun_cloud
git checkout claude/loading-request-lg3rym
claude
```

起動すると `CLAUDE.md` が自動で読まれ、この案件の線（評価と言わない／謝らない／
EXPを人事評価に使わない など）がそのまま効く。

⭐ **`docs/` を読ませてから頼むと早い。**
「`docs/設置手順_AppsScript_20260831.md` を読んで、ステップ3から進めて」で通じる。

## 引き継ぎのしかた

セッション同士は会話しない。**渡したいことはリポジトリに書く。**

| 渡すもの | 置き場所 |
|---|---|
| 決まったこと・経緯 | `docs/` に文書として |
| 何が済んで何が残っているか | `gas/manifest.tsv` の `done` / `pending` |
| 守る線 | `CLAUDE.md` |
| 次にやること | `docs/はじめに_この案件のさわり方.md` の「いま手が空いている人に向く仕事」 |

## SSHでクラウドからPCを操作する案について

**この規模では割に合わない。** PCを常時起動し、ポートを開け、鍵を管理する手間に対して、
得られるのは「移動中に実行できる」だけ。

移動中にやりたいことは、たいてい**考える・書く**側なので、クラウドで足りる。
実行はPCの前に戻ってからでよい。
